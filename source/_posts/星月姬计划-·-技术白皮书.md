## 一、项目概述

星月姬计划（Project LUNARIS）是一套**本地优先、开源开放的 AI 跨端协同中枢系统**。它以 Windows PC（x64）为算力核心，通过语音或文本交互，统一调度局域网内所有智能设备——包括 Linux 主机、Android/HarmonyOS 移动设备、智能家居及各类开发板——在无需 Root、无需解锁 Bootloader、不触碰系统红线的前提下，合法合规地执行跨端指令。

项目名称源于拉丁语 **LUNARIS**（月之彼端），寓意打破设备孤岛，触及智能交互的终极形态。它拒绝将隐私上传云端，拒绝让数据流经第三方 SaaS，旨在把数字主权重新交还给每一位极客、开发者和决策者。

**命名彩蛋**：项目正式名为“星月姬”，候选唤醒词保留“离心机”——源自初代命名“璃星姬”的谐音梗。当用户希望开启“冷酷工具人”模式时，“离心机”意味着“高速分离杂念，精准执行物理指令”。

与市面上其他 AI 助手（小爱同学、天猫精灵、Siri 等）的本质区别在于：星月姬的所有语音识别（STT）、大模型推理（LLM）及 Agent 决策均在本地 PC 完成，**断网依旧智能，隐私绝不离开家门**。

## 二、核心哲学

### 2.1 异构统御

无视生态壁垒，用同一套自然语言统一指挥 Android、HarmonyOS、Linux、Windows 及 IoT 设备。无论设备来自哪个厂商、运行何种系统，在星月姬眼中都是可调度的“执行单元”。

### 2.2 本地智脑

所有语音识别、大模型推理及 Agent 决策均在本地 PC 运行。断网依旧智能，隐私绝不离开家门。

### 2.3 非侵入式控制

恪守“常规权限”边界——Android 端利用官方提供的 AccessibilityService 与无线 ADB 调试，Linux 端仅操作用户级服务（systemctl --user），Windows 端调用官方 API。在绝对安全的前提下实现深度自动化。

### 2.4 开源与商业共生

核心引擎遵循 **GPL v3** 开源，同时通过贡献者许可协议（CLA）保留未来“双授权”（Dual Licensing）的可能——开源版供社区自由使用，商业闭源版供企业集成，确保项目可持续。

## 三、人格化设计：三层架构

星月姬区别于普通 AI 助手的核心，在于其“人格化”的三层架构设计：

### 3.1 底层大脑：大模型天赋

大模型（如 DeepSeek V4、Qwen2.5 等）是星月姬的“天赋”——天生聪明，反应快，能处理海量信息。但它天生是空白的，需要后天塑造。

### 3.2 中间层：人设提示词（性格说明书）

提示词不是命令 AI 去做什么的流程图，而是一段“性格说明书”：你是一个善于倾听的向导，你喜欢用比喻讲故事，你相信答案应该由用户自己发现……它告诉星月姬“你要成为什么样的人”。

### 3.3 知识库：阅历与记忆

知识库是星月姬“读过的书、走过的路”——不是冰冷的数据库，而是一本本“山海经”：有案例，有故事，有前人的思考，有你反复打磨的原则。通过 RAG 向量检索，星月姬实现永久记忆，即使重启，依然记得与用户的每一次交互。

**三层架构的类比**：大模型是孩子的天赋，提示词是你教他的做人道理，知识库是你给他读的书、讲的故事。他不再是你的“工具”，而是一个独立的伙伴。

## 四、技术架构

### 4.1 三层解耦架构

| 层级 | 职责 | 关键技术 |
| :--- | :--- | :--- |
| **PC端——感知与决策层** | 语音唤醒与识别、大模型推理、意图识别与路由 | Porcupine、Whisper.cpp、llama.cpp、LangChain |
| **服务端——权限与适配层** | 设备注册与鉴权、指令下发、操作审计、安全栅栏 | 自研私有 API（RESTful/WebSocket）、TLS 加密 |
| **终端——执行层** | 接收指令并执行具体操作 | Android 无障碍服务/ADB、Linux systemd、MQTT |

### 4.2 多模型协作大脑

星月姬不依赖单一模型，而是采用多模型分工协作机制：

- **通用聊天**：Qwen2.5 / DeepSeek-V3 量化版（GGUF 格式，通过 llama.cpp 推理）
- **复杂/多模态任务**：Qwen-VL / LLaVA（处理图像识别、文档理解等）
- **工具调用（Function Calling）**：上述模型原生支持，让 AI 自主决定何时调用“开灯”、“拨号”、“发消息”等函数
- **长期记忆**：RAG（检索增强生成）方案，使用 Chroma 或 FAISS 作为向量数据库

### 4.3 安全栅栏（操作回滚）

在执行“删除文件”、“修改系统设置”等高风险操作前，星月姬自动联动：

- **Windows**：系统还原点
- **Linux**：Timeshift 快照
- **Android**：bmgr（备份管理器）

一旦指令执行导致异常，用户只需说一句“撤销上一步”，PC 大脑立即下发回滚指令。

## 五、功能矩阵

### 5.1 多模型协作大脑

- 本地运行 Qwen2.5 等量化大模型
- 简单聊天与复杂任务（多模态/Agent）自动分流
- RAG 向量检索实现永久记忆
- 支持 Function Calling，AI 自主决定调用何种工具

### 5.2 全离线语音交互

- **唤醒词**：默认“星月姬”，彩蛋“离心机”（基于 Porcupine 离线唤醒引擎）
- **语音识别（STT）**：Whisper.cpp 本地离线识别
- **语音合成（TTS）**：Edge TTS（轻量）或 Coqui TTS（可克隆声音）
- **毫秒级响应，隐私绝不踏出家门半步**

### 5.3 PC 端控制中心（Windows/Linux）

- 打开/关闭应用程序
- 模拟键盘鼠标操作（Linux xdotool / Windows SendInput）
- 系统监控（CPU/内存/进程）
- 用户级服务管理（systemctl --user）
- 文件操作与通知推送

### 5.4 移动设备控制（Android/HarmonyOS）

- **调起原生拨号**：通过 ACTION_CALL Intent 实现 SIM 卡自动拨号，手指零点击
- **无障碍自动化**：利用 AccessibilityService 实现应用间跳转、模拟点击、表单填写
- **通知监听与回复**：监听手机通知，由 PC 大脑决定是朗读、忽略还是自动回复
- **无线 ADB 调试**：无需 USB 连接，局域网内执行截图、输入文字、安装应用等操作
- **无需解锁 BL 或 Root**，走的全是官方留给开发者的“正门”

### 5.5 智能家居与开发板

- 接入 Home Assistant（开源家庭自动化平台，本地控制与隐私优先）
- 直连 MQTT 协议，控制灯光、空调、门禁
- 支持 ESP 系列开发板（ESP Weaver SDK 实现局域网内发现与控制）
- 支持 **H-DDL（异构设备描述语言）**：每台设备以 JSON 格式声明“能力清单”，新增设备像安装驱动一样简单

### 5.6 虚拟形象交互

- 支持 Live2D 2D 动态形象（快速启动方案）
- 支持 VRM 3D 模型（高自由度，配合 Three.js 渲染）
- 可缩小为浮窗挂在桌面置于最上层
- 亦可展开全屏对话界面，提供沉浸式交互体验

## 六、特色亮点

### 6.1 跨端指令闭环（企业级场景验证）

PC 端语音指令 → Agent 解析意图 → 私有 API 下发 → 手机端执行（如自动拨号）→ 结果回传。全过程不依赖任何第三方 SaaS，数据流转严格限定在内部服务器与官方可信通道之间。

### 6.2 关注点分离

PC 端（感知与决策）、服务端（权限与适配）、终端（执行）三层解耦，单点故障不影响全局。新增功能只需在 Agent 意图识别层增加“动作-对象”映射，并在服务端注册执行器——新功能上线周期从“周级”压缩至“天级”。

### 6.3 异构设备统一抽象

无论设备是 Android 手机、Linux 服务器、还是智能灯泡，在星月姬眼中都是统一的“可调度资源”。Agent 调度时只看 H-DDL 能力清单，不问底层是 ADB、SSH 还是 MQTT。

### 6.4 人格化双模

- **星月姬模式**：温柔陪伴，情感化交互
- **离心机模式**：冷酷工具，高效执行物理指令
- 同一灵魂，两种人格，用户自由切换

## 七、开源与生态

### 7.1 开源协议

本项目基于 **GPL v3** 协议开源。GPL v3 是典型的“强 Copyleft”协议，其核心宗旨是保障用户运行、修改和共享自由软件的自由，同时要求这种自由在衍生作品中得以延续。

### 7.2 双授权机制

项目引入 CLA（贡献者许可协议），所有外部贡献者须将代码版权授予项目所有者，允许项目以多重许可证（包括商业闭源）形式分发。这意味着：

- **开源版（GPL v3）**：免费供社区使用，任何修改必须开源
- **商业版（闭源授权）**：供企业集成至闭源产品，按受控设备数量/年收取授权费

### 7.3 生态兼容

欢迎一切兼容 GPL v3 的开源项目集成。允许企业基于本引擎构建闭源插件（不与核心 GPL 代码静态链接的前提下）。
